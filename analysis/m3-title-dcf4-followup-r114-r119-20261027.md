# Steel Battalion title, crash, and DCF4 follow-up — r114–r119 (2026-10-27)

## Result

No run in this series reached the pilot menu or `NOW LOADING`; no loader dependency or first mission frame was verified. Keep the observed startup faults, black framebuffer, expensive raster batches, and DCF4 wait as separate findings.

The clean no-helper starts r115 and r116 both crashed about 22 seconds after launch at native RVA `0x064BAC0C`, with a read at `0x91B7F52F` (guest address `0x91B6F52F`). DIA resolves this instruction to `sample_tex` in `nv2a_pb_exec.c`; it is a repeatable renderer-side startup fault for that executable hash. r117 also faulted inside `sample_tex` after logging 160 texture samples. Those samples describe a 512×512 DXT1 texture at `0x803DF800`; the added `xbox_IsXboxAddress` probe marked that base outside its simple Xbox-range predicate, but this is not sufficient to call it the bad address or establish the fault cause.

r118, built with the expanded texture trace, failed differently: generated guest code at `sub_0018F015` attempted to unlink a DirectSound voice-list node. The faulting node was guest `0x81ED6FFC`; its `+0x0C` link was `0xDEA9AAFB`, unmapped. The stack returned through `0x00190A42` in `sub_001909B6`. This confirms a separate DirectSound list fault and does not explain r115–r117's texture read.

r119 stayed alive on a black framebuffer until the UI plateau supervisor stopped only PID `129656` after 300 seconds without framebuffer or input change. It did reproduce an unsignaled DCF4 event wait at frame `0x125`: `wait-DCF4[134]` at guest callsite `0x00211F3B` has no matching return. Event signal remained `0`; the callback count stopped at 430 while the NV2A tick continued. This is a real synchronization wait in the title/startup path, but it is not the requested loading-stage wait because the game never reached `NOW LOADING`.

At the wait, the DCF4 producer record shows descriptor `0x80083720`, method `0x00040100`, parameter `5`; the post-flush marker still has signal `0`. The threshold snapshot reports result `0x000024F8`, frame `0x125`, counter `0x505`, target `0x4FB`, semaphore `0x4F7`, event `0`, and queue fields `0/0x0F`. The next DCF4 callback is `n=430`, argument `0x01080021`, selected index 1, target `0x00216EC9`; the prior recurring argument `0x00000005` selected index 5 and target `0x0021701E`. No DCF4 return was logged after wait 134.

The raster trace is material but not synchronized closely enough to explain the missing DCF4 signal. At tick `383216984`, about 1.9 seconds before the wait, four raster threads completed 224 batches / 448 triangles with 9,882,624 pixel writes; batch wall time was 621.68 ms and aggregate raster-active time 2,390.46 ms. At the final NV2A snapshot, ticks advanced to 14,400 while callback count stayed 430 and frame/counter/target/fence stayed `0x125 / 0x505 / 0x4FB / 0x501`; DMA PUT and GET were both `0x5E5C` in the latest register snapshot. This rules out an accumulating pushbuffer ring at that snapshot, but worker completion telemetry at the wait is missing, so raster-worker backlog is not ruled out as a contributor to a missed signal.
